# 계획 -- CR · Sensor · Policy · Validate/Arbitrate/Guard · Claude Code 장착 (2026-10-02)

지금 있는 것과 역할은 [`역할.md`](역할.md). 이 문서는 **앞으로**다. 단계마다 들어가는 조건 · 내놓을 것 · 시험 · 잴 것 · 나가는 조건을 적는다.

## 0. 먼저 바로잡을 이해 하나 -- 캐시는 뜻이 아니라 바이트다

"의미가 조금 달라졌다고 캐시를 못 읽는다" 처럼 보였던 것의 실제(역할.md K4):

- provider 의 프롬프트 캐시는 **바이트의 앞부분 일치**다. 뜻이 같아도 바이트가 하나 다르면 그 뒤는 전부 새로 쓴다.
  뜻이 달라도 앞부분 바이트가 같으면 그만큼은 읽는다.
- 캐시 항목은 **캐시 지점**에서만 생긴다. claude -p 는 지점을 프롬프트 끝에만 둬서, 시스템 글이 같아도 사용자 글이 다르면 0 을 읽었다.

그래서 두 가지를 갈라 짓는다:

| | 무엇을 아끼나 | 어디서 |
|---|---|---|
| **provider 캐시** (바이트) | 같은 앞부분의 재처리 | CR 이 앞부분을 바이트까지 고정하고(stable_prefix), 에이전트 하네스에서는 **덧붙이기만** 한다(앞을 고치지 않는다). Claude API 는 시스템 글 끝에 캐시 지점 |
| **결정 재사용** (뜻) | 같은 상태에서 같은 결정을 다시 내리는 LLM 턴 자체 | MS 쪽. 상태 해시가 같으면 직전 CD · 결론을 다시 쓴다(walp 실행 정책층 P1 과 같은 생각). 아래 3 단계 |

## 1. 목표 구조

```
TELEMETRY      API 실행 기록(RunRecord) · Claude Code 대화 기록 · 훅 사건          "무슨 일이 일어났나"
   ↓
SENSOR         llmsensor: Reading(OK·SUSPECT·FAULT·UNKNOWN) · 잔차 · 증거 융합 Q    재기만 한다 -- 결정하지 않는다
   ↓
STATE          MS 모형: 사용 상태 8 + 센서 상태(아래)                           "Model 에 의해 무엇을 뜻하나"
   ↓
POLICY         무엇을 목표로 · 어디까지 해도 되나: 예산 · 검증 엄격도 · 가드 문턱 · provider    규칙. 판본 붙음
   ↓
CR → CD        Context Runtime: 무엇을 보이고 어떻게 말하나(KEEP…COMPRESS · 배치 · 재사용)   지금 MS 안(cr.py), 나중에 독립
   ↓
PROVIDER → LLM → PROPOSAL
   ↓
VALIDATE       형식 · 증거가 주장을 받치나 (llmsensor Verifier 를 다시 짓지 않고 쓴다)
ARBITRATE      이 제안을 지금 상태에서 받나 (WALP A0~A8, 있음)
GUARD          상태 · 정책 · 프롬프트와 무관하게 늘 지키는 불변식 (예산 상한 · 되돌릴 수 없는 동작 · 고리 끊기 · 꺼짐 스위치)
   ↓
TOOL → TELEMETRY
```

**누가 무엇을 멈출 수 있나** -- 겹치지 않게:

| 층 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|
| Sensor | 판독을 낸다 | 아무것도 막지 못한다 |
| Policy | 수(예산 · 문턱 · 엄격도)를 정한다 | 개별 제안을 판정하지 못한다 |
| CR | 보일 것을 정한다 | 정책이 정한 상한을 넘지 못한다 · 제안을 판정하지 못한다 |
| Validate | 이 출력을 RETRY · DEGRADE · REJECT 로 돌린다 | 도구를 허가하지 못한다 |
| Arbitrate | 이 제안을 ALLOW · DENY | 불변식을 풀지 못한다 |
| Guard | 루프 전체를 멈춘다 · 무조건 DENY | 허가를 **더하지** 못한다(닫는 쪽으로만) |

## 2. 단계

### 1 단계 -- CR 을 층으로 세운다 ✅ (2026-10-02, `cr-1`)

- `ms/cr.py` 가 맥락 · 프롬프트를 짓는 **유일한** 자리다. 입력: 상태 스냅숏 · 요청 · 질의 결과. 출력: ContextDecision(최소 맥락 + 정규
  프롬프트 + 결정 기록). Pipeline · Runtime 은 CD 를 쓰기만 한다. 시험이 그 경계를 붙든다(우회하면 빨개진다).
- 결정 기록에 `prefix_hash`(캐시 앞부분의 지문)를 남긴다. 평가가 칸마다 "다른 앞부분 수" 를 센다 -- 캐시가 깨지는지 수로 보인다.
- 지금은 에이전트가 이 역할을 MS 안에서 맡는다. 독립 계층으로 옮길 때 끊을 자리는 `cr.py` 하나다.

### 2 단계 -- Sensor 배선 (CR 다음)

- **들어가는 조건**: 1 단계 끝. Sensor 저장소의 공개 API(`sense()` · `Reading` · `Verifier`) 그대로 쓴다.
- **내놓을 것** `ms/sensing.py`: llmsensor 의 Reading · Q · 잔차를 **텔레메트리 신호**로 편다(`sensor.<이름>.status` · `sensor.q` …).
  Reading 은 상태가 아니다(원칙 1) -- MS 모형이 해석한다. 새 상태(usage-model-3 또는 별도 Sensing 모형):

  | 상태 | 해석의 재료 |
  |---|---|
  | `outcome_confidence` | Q 의 띠. Q 가 보정 전이면(`calibrated=false`) **순서 점수**로만 -- HIGH 를 주지 않는다 |
  | `false_success_risk` | 일관성 센서의 claim FAULT("됐다" 는데 마지막 검증 실패) |
  | `loop_risk` | 행동 센서의 고리 · ABAB 진동 |
  | `cost_anomaly` | 토큰 잔차(성능모형 대비 팽창) |

  UNKNOWN 은 모름으로 남는다(OK 로 세지 않는다). Verifier 의 판정(ACCEPT …)은 **상태로 안 넣는다** -- 결정이므로 Validate 로 간다.
- **의존성**: llmsensor 도 표준 라이브러리만 쓴다. MS 는 그것 없이도 돌아야 한다(선택 import, 없으면 센서 상태는 모름).
- **시험**: 판독이 그래프에 바로 안 들어간다 · UNKNOWN → 모름 · 같은 과업을 provider 둘이 해도 센서 상태의 뜻이 같다 · 우회하면 빨개진다.
- **조사 먼저**: 관측 도구(LangSmith · Langfuse · Helicone 등)가 판독을 맥락 결정으로 되먹이는지 -- `paper/선행조사/` 에 먼저.

### 3 단계 -- Sensor 아래 Policy, 그리고 CR v2

- **Policy**(`ms/policy.py` 를 둘로 가른다): 지금 `policy.py` 에 섞인 것 중 **수와 한계**(예산 · 검증 엄격도 · 가드 문턱 · provider)만
  Policy 에 남기고, **어떻게 보일지**는 CR 로 옮긴다. Policy 는 CR 에 **제약**(최대 맥락 · 반드시 넣을 것)을 주고, CR 은 그 안에서 정한다.
  Sensor Verifier 의 정책 제안(token_budget · retry_limit · terminate_on_repeat · route)은 Policy 의 **입력**이다, 명령이 아니다.
- **CR v2**(`cr-2`):
  - **결정 재사용(REUSE)** -- 상태 해시가 같으면 직전 CD 를 다시 쓴다. 뜻의 캐시는 여기서만 한다
  - **덧붙이기만** -- 에이전트 하네스(Claude Code)에서는 앞의 맥락을 고치지 않고 덧붙인다(바이트 캐시를 지킨다)
  - **꺼냄 비용을 셈에 넣는다** -- 역할.md F2(적응 맥락이 꺼냄을 늘리고 느리다): `tool_churn` · 꺼냄 비율이 높으면 덜 자른다
- **잴 것**: F2 를 사전등록하고 잰다(덜 자르면 꺼냄과 지연이 주는가).

### 4 단계 -- Validate · Arbitrate · Guard (에이전트 몫)

| | 무엇으로 | 새로 지을 것 |
|---|---|---|
| Validate | MS 의 형식 검사(A0) + llmsensor `Verifier`(외부 결과 · 일관성 · 제약 근거) | 둘을 한 판정으로 묶는 순서 규칙. RETRY 는 CR 의 다음 판 입력으로 |
| Arbitrate | WALP A1~A8 (있음) | A7(허가)을 Guard 로 옮길지 결정(아래 열린 결정) |
| Guard | 새로 `ms/guard.py` | 세션 상한(토큰 · 비용 · 시간) · 되돌릴 수 없는 동작 허가 · 고리 끊기(Sensor loop FAULT 면 멈춤) · 꺼짐 스위치 · **닫힌 쪽 실패** |

- 순서: Validate → Arbitrate → Guard → Tool. Guard 가 도구 바로 앞이다.
- **시험**: 각 층이 자기 몫만 한다(위 "누가 무엇을 멈출 수 있나" 표를 시험으로) · Guard 는 무엇을 넣어도 허가를 넓히지 못한다 ·
  Guard 가 터지면 DENY.

### 5 단계 -- Claude Code 에 단다 (훅, 그림자 먼저)

훅 계약(문서 확인 2026-10-02, code.claude.com/docs/en/hooks.md):

| 훅 | 받는 것 | 낼 수 있는 것 | MS 에서 |
|---|---|---|---|
| SessionStart | session_id · cwd · source | additionalContext | MS 세션 열기 |
| UserPromptSubmit | prompt | additionalContext · block | CR: 최소 맥락을 **덧붙인다**(시스템 알림으로 들어간다) |
| PreToolUse | tool_name · tool_input | permissionDecision allow · deny · ask · defer + 까닭 · updatedInput | Arbitrate + Guard |
| PostToolUse | tool_input · tool_response | additionalContext · block · updatedToolOutput | 텔레메트리 → Sensor · Validate |
| Stop | stop_hook_active | decision block(멈추지 못하게) | Validate: "끝났다" 는 주장을 증거로(false success) |

**알고 들어갈 것**:
- **훅이 터지면 열린다.** 종료 코드 2 가 아닌 비정상 종료 + JSON 아닌 출력은 "막지 않는 오류" 로 처리되고 동작이 **진행된다**.
  Guard 는 모든 예외를 스스로 잡아 deny JSON 을 내야 한다(시험으로 붙든다).
- 문서에 없는 것: 시간 초과 때 동작이 어떻게 되나 · additionalContext 와 프롬프트 캐시의 관계 · SubagentStop 의 꼴 ·
  환경 변수로 훅 끄기(문서에는 `disableAllHooks` 설정만). **추측하지 않고 탐침으로 잰다**(K4 처럼).
- 순서: `ms hook install --shadow`(기록만, 아무것도 안 막음 -- walp `install-shadow` 선례) → 그림자 기록으로 사전등록 평가 →
  통과한 훅만 켠다. 처음부터 막지 않는다.

### 6 단계 -- 진짜 API 평가 (사용자 키)

- 사전등록(`eval/PREREG_적응정책.md` + 고침 1) 그대로: A~F · 반복 3 · `--order interleaved --fresh`.
- 추가로 Claude API 캐시 지점 탐침: 같은 시스템 · 다른 사용자 글 두 번 → 둘째의 `cache_read_input_tokens > 0` 인가. claude -p 에서는 0 이었다.
- 이 평가가 2~5 단계보다 먼저 와도 된다(코드와 무관하게 돌 수 있다).

## 3. 열린 결정 -- 사용자가 정할 것

| # | 물음 | 제안 |
|---|---|---|
| 1 | Policy 와 CR 의 경계: Policy 는 **수와 한계**, CR 은 **그 안에서 어떻게** -- 이렇게 가르면 되나 | 그렇게 가르자 |
| 2 | 허가(A7: external · irreversible)는 Arbitrate 에 두나 Guard 로 옮기나 | Guard 로. 상태와 무관한 불변식이므로 |
| 3 | Claude Code 훅이 터질 때 | 그림자 단계는 열린 쪽(기록 실패가 작업을 막지 않게), 켠 뒤 PreToolUse 는 닫힌 쪽 + 꺼짐 스위치 |
| 4 | Sensor 를 어떻게 가져오나 | `pip install git+https://github.com/cogito5170/Sensor` 선택 의존. MS 에 복사하지 않는다 |
| 5 | CR 을 나중에 어디로 옮기나(별 저장소 · 별 프로세스 · MS 안의 별 패키지) | 2~3 단계를 지나 CR 의 입출력이 굳은 뒤 정하자 |
| 6 | 2 단계(Sensor)와 6 단계(API 평가) 중 무엇을 먼저 | 6 은 키만 있으면 바로 돈다. 가설의 답이 먼저 필요하면 6 |

## 4. 일하는 방식(그대로 지킨다)

조사를 코드보다 먼저 · 측정 전에 사전등록 / 미리 정한 읽기 · 사소한 설명을 재서 가림 · 시험은 망가뜨려서 확인 · 모의와 claude-cli 는 증거가 아니라고 적음 ·
수를 말할 때 구간과 함께.
