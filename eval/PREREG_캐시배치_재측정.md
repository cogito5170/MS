# 재측정 메모 3 -- 캐시를 지키는 프롬프트 배치(prompt-text-3) (2026-10-02, 돌리기 전)

**사전등록 `PREREG_적응정책.md` 의 실행이 아니다**(claude-cli 배선 측정). 재측정 2 에서 본 것: 적응 프롬프트(F)가 상태에 따라
시스템 글을 바꿔 provider 캐시를 못 읽었고(캐시 안 된 입력 +822 · 비용 +$0.0036/과업), 동시에 B · D 는 같은 과업을 한 시간 안에
되풀이해 프롬프트 **전체**를 캐시에서 읽었다(99.9%) -- 둘이 겹쳐 차이가 부풀었다.

## 바꾼 것

1. **배치 stable_prefix (prompt-text-3)** -- 시스템 글을 모든 계획 · 상태가 같이 쓰는 한 덩어리로 고정(지시 full + 칸 설명 + args 메모).
   계획이 바꾸는 것(예시 · 도구 허용 줄)은 사용자 글로, 지침은 STATE **뒤**로. `instruction_mode=concise` 는 이 배치에서 적용하지 않고
   `unsupported` 에 적는다(지시문을 줄이면 앞부분이 바뀐다). 시험이 "모든 계획에서 Claude 요청의 system 이 바이트까지 같다" 를 붙든다.
2. **`--fresh`** -- 실행마다 다른 표지를 시스템 글 바로 뒤에 붙인다. 되풀이한 과업이 프롬프트 전체를 캐시에서 읽는 일을 막고,
   진짜 쓰임처럼 앞부분(시스템 글)만 캐시되게 한다.

정책 규칙(`ctx-adaptive-1` · `prompt-adaptive-1`) · 사용 모형(`usage-model-2`)은 그대로다.

## 돌릴 것

claude-cli · B · D · F · 반복 2 · 과업 7(고치지 않음) · `--order interleaved --seed 0 --fresh` · 배치 stable_prefix.
